# S1 P2 原型与公共方法提取器

## 五层提取更新（2026-09-27）

`ExtractMethod` 现从每个命中帧沿同一线程向调用者方向最多枚举5个非JDK方法帧。JDK帧不占层数；无法定位的非JDK帧（包括合成lambda）占一层，记录失败后继续，不冒充成功。栈省略或编号断层仍停止，不能跨过缺失调用链。

每层是 `results` 中独立对象，带 `method_layer` 和该层完整 `stack_path` 快照；顶层新增 `max_method_layers=5`。混合成功/未定位返回 `PARTIAL`，P2只处理层级状态为 `METHOD_LOCATED` 的结果，并按路径/方法起始行去重补丁。

## 文件与接口

- `repair/main/kotlin/src/pool/extract_method.kt`：`ExtractMethod`，取代 Q16Repairer。消费现有 Q1 定位对象，支持可选类别过滤；默认提取所有命中类别的方法上下文，不生成补丁。未来其他分类器需适配相同输入结构，当前未声称已经接入 Q2–Q5。
- `repair/main/kotlin/src/pool/s1_expensive_work/P2ExpensiveWorkRelocation.kt`：P2 候选补丁生成器。
- 原 `Q16Repairer.kt` 已移除；构建脚本、入口及测试已更新。旧 `--s1-q16-method` 仍作兼容选项，过滤 Q1.6 并保留 `s1_q16` 输出别名。

调用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File repair/main/scripts/build-q1.ps1 -Python D:/intellij-community-master/out/edt-freeze-finder/layout-python/python.exe
$env:Q1_CLASSPATH = (Get-Content "$env:TEMP/repair-q1-build/classpath.txt" -Raw).Trim()
python repair/main/python/repair.py --input finder.jsonl --output repair.jsonl --q1-classpath $env:Q1_CLASSPATH --s1-p2
```

`--extract-method` 只提取；`--s1-p2` 自动提取并尝试生成补丁；均不能与 `--q1-count-only` 并用。输出路径必须尚不存在。

`q1.method_context` 的 schema 为 `repair-method-context/1`，保留定位状态、命中类别、完整方法正文、原始帧引用和栈路径。

`q1.s1_p2` 的 schema 为 `repair-s1-p2-proposal/1`：

- `strategy=PRECOMPUTE_OUTSIDE_EDT`。
- `status=CANDIDATE_PATCH/NO_SUPPORTED_METHOD`，`applied=false`。
- `proposals` 包含方法引用、相对路径、预期文件 SHA256、起止行号、原正文、替换正文、统一 diff；不支持或源码变化保留原因。
- 生成补丁不等于实施修复，入口 `repair_status` 仍为 `NOT_STARTED`。

## 第一版覆盖边界

仅支持已核对的 `AppIcon$Win7AppIcon._setOkBadge` 原方法形态：类/方法身份和方法正文 SHA256 精确匹配，生成前重新校验文件哈希、路径边界、方法范围及新增字段名称冲突。不是任意 Q1.6 方法的通用异步改写器，不按 Excel 行号硬编码匹配。

候选变换：

1. 后台 `CompletableFuture.supplyAsync` 完成资源读取、PNG 解码及 ICO 字节生成，关闭输入流。
2. EDT 使用 WeakHashMap 保存每个窗口的请求标识；后台回调只持有弱窗口引用。
3. 重复请求复用准备任务；显示/隐藏更新请求标识；回调检查标识、窗口有效性及 displayable 状态。
4. EDT 创建原生图标并更新任务栏，复用原有 myOkIcon；不执行 get/join 等同步等待。
5. 准备失败在 EDT 清空失败任务，后续请求可重试。缓存成功的字节供后续窗口使用。

这是使用 JDK common pool 的候选原型。应用级执行器、模态/退出语义、真实窗口以及 Windows 原生资源生命周期仍需目标 IDE 验证；未直接应用于生产源码。Context7 Java 查询未返回相关 API 文档，线程行为以本次运行测试为证，不声称该查询验证了 IntelliJ API 契约。
