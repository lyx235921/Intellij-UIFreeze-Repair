第 4746 行真实堆栈中的关键路径，从上层调用到耗时操作简化如下：


原问题是文件属性查询/内容读取在 EDT 的文档重载路径中同步发生。真实堆栈不能单独给出当时文件大小、路径、磁盘延迟或完整复现步骤。

当前 P1 候选选择“VFS 事件应用之后，文档更新关键区之前”准备磁盘字节：

1. 捕获事件、文件和文档版本。
2. 后台直接读取磁盘，前后校验身份、大小和修改时间。
3. 通过版本检查后回到 EDT，按原 BOM/字符集重置顺序解码并更新文档。
4. 过期结果丢弃，新事件替代旧请求；读失败/不稳定最多尝试三次，EDT 不等待。

### 当前候选的行为（示意代码，非完整补丁）

```java
void contentsChanged(Event event) {
  Request request = captureVersions(event);
  executeOnPooledThread(() -> {
    byte[] bytes = readStableDiskSnapshot(request);
    invokeLater(() -> {
      if (!isCurrent(request)) return;
      commitDocumentUsingOriginalDecoder(request, bytes);
    });
  });
  // 此处立即返回，文档尚未更新。
}
```

因此可能出现：

```text
EDT：应用 VFS 新版本 → contentsChanged 启动后台任务 → 返回给刷新调用方
调用方：读取 document，仍然得到旧内容/旧版本
BGT：完成读取
EDT：稍后更新 document
```

保留公开 `reloadFromDisk` 的同步行为，不能解决 `contentsChanged` 已经提前返回的问题。刷新完成后的回调或依赖文档版本的调用方也需要验证。

不能用下面的写法补救：

```java
// 错误修补示例：再次让 EDT 等待后台结果。
byte[] bytes = backgroundRead.get();
updateDocument(bytes);
```

这会重新引入 EDT 等待；若完成过程还需要 EDT，甚至可能形成相互等待。
